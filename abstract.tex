\abstracttitle{Accelerating Open-Source InSAR Time-Series Analysis on Consumer GPUs: A PyTorch-Based Network Inversion Solver for MintPy}

\abstractauthors{Syota Sasaki\affmark{*,1}}
\abstractaffil{\affmark{1}Earthsea Wizard, Japan}
\abstractemail{syota.sasaki@earthsea-wizard.com}
\abstractkeywords{InSAR, GPU acceleration, PyTorch, time-series analysis, open-source software}

Interferometric SAR (InSAR) time-series analysis has become a standard tool for measuring ground deformation associated with volcanoes, earthquakes, and land subsidence. With the continuous acquisitions of Sentinel-1 and the arrival of the NASA-ISRO SAR mission (NISAR) [1], the volume of interferometric data available for such analysis is growing faster than the throughput of the processing software that consumes it. MintPy [2], one of the most widely used open-source packages for small-baseline (SBAS) time-series analysis, executes its most expensive step---the least-squares inversion of the interferogram network into a displacement time series---as a per-chunk CPU computation, which dominates the end-to-end runtime of its \textit{smallbaselineApp} workflow. The objective of this work is to remove that bottleneck with GPU acceleration while keeping the software accessible: no HPC cluster, no CUDA programming on the user side, and no change to the default CPU behavior.

The methodology reformulates the pixel-wise least-squares inversion as a batched linear-algebra problem in PyTorch. Instead of solving each system with a general-purpose least-squares routine, the solver assembles the normal equations and applies batched Cholesky factorization in single precision, streaming pixel chunks sized to the available GPU memory. The implementation is deliberately minimally invasive: it lives in a separate GPU subpackage, is selected by a single configuration key (\texttt{mintpy.networkInversion.solver = torch}), and leaves the existing CPU path byte-for-byte unchanged. The same design was applied to the DEM-error (topographic residual) correction step. Numerical agreement with the CPU reference is enforced by a validation gate on the normalized root-mean-square difference of the resulting time series.

The solver was evaluated on a consumer workstation GPU (NVIDIA GeForce RTX 5080, 16~GB). On the Fernandina Sentinel-1 tutorial dataset, the network inversion kernel runs 16.5$\times$ faster than the CPU baseline. On a larger Gal\'apagos scene (3.4 million pixels, 475 interferograms), the inversion step drops from 6{,}189~s to 170~s---a 36.4$\times$ step-level and 44.4$\times$ kernel-level speedup---within 7.6~GB of GPU memory. A five-scene benchmark sweep spanning two orders of magnitude in problem size shows speedups of 5.2--93.8$\times$, and the DEM-error correction achieves 6.2$\times$ on the same large scene. Across all cases the maximum normalized RMS difference against the CPU reference is on the order of $10^{-5}$, consistent with single-precision round-off, and the full 18-step \textit{smallbaselineApp} workflow completes end-to-end with the GPU solver enabled.

These results turn multi-hour network inversions into minutes on commodity hardware, shortening the path from SAR acquisition to a usable deformation time series---a practical enabler for rapid-response volcano and earthquake monitoring and for routine national-scale subsidence surveillance in the NISAR era. The work has been submitted upstream to the MintPy project as an opt-in feature, and the benchmark harness and reports are public for reproducibility. By demonstrating order-of-magnitude gains on a single consumer GPU rather than a dedicated cluster, this contribution lowers the entry barrier for research groups and agencies that operate InSAR monitoring on limited budgets.
